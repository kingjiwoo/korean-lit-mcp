# 한국고전종합DB 검색 연동

확인일: 2026-11-01. 범위: 공식 검색 API와 검색 결과 발췌. production 배포 제외.

## 확인한 사실

[소개](https://db.itkc.or.kr/etc/openAPI?type=page1)는 외부 부가 서비스에서 사용할 검색 API라고 설명한다. [호출 규칙](https://db.itkc.or.kr/etc/openAPI?type=page2)에는 인증키·회원가입 파라미터가 없다. 쿠키나 키 없이 HTTPS GET으로 실제 XML 응답을 받았고 이번 파서로 읽었다.

검색어 `春`, 시작 0, 결과 수 1의 실증 결과다. 검색 총건수는 시점에 따라 달라지며 작품 수가 아니다.

| 검색 대상 | 총 검색건수 | 반환건수 | 검색필드 문자 수 |
| --- | --- | --- | --- |
| GO_BD | 18,658 | 1 | 151 |
| MO_BD | 140,009 | 1 | 151 |
| KP_BD | 4,090 | 1 | 310 |
| MO_GS | 14,395 | 1 | 25 |

`검색필드`는 검색 강조 마크업이 XML에서 이스케이프된 문자열이다. 이를 정본이나 전문으로 바꾸지 않고 검색 발췌로 반환한다. 자료 ID, 제목, 서명, 저자, 권차를 함께 표시한다. 원 API 데이터는 실행 중에만 확인했으며 원문 fixture를 저장하지 않았다. 테스트는 합성 XML이다.

## 결정

`search_classical_text` 하나에서 본문과 기사명 검색을 제공한다. collection은 고전원문·한국문집총간·한국고전총간이다. 임의 URL이나 API 쿼리 문법을 사용자 입력으로 받지 않는다. 호출 주소는 운영자가 `ITKC_API_URL` 환경변수로 설정하며 코드 기본값은 없다. 미설정은 명시적인 오류다.

기존 `search_works`는 검수 판본·국립중앙도서관 서지 검색 계약을 유지한다. 외부 기사 검색 결과를 검수 작품 ID에 자동 연결하면 동명이작과 판본 혼동이 생기므로 새 도구에서 탐색한다. `get_passage`와 `verify_quote`는 검수 자료 경로를 유지한다.

검색 안내에서 별도 전문 상세 API는 발견하지 못했다. 자료 ID 기반 공식 상세 페이지 링크를 반환하지만, 내부 웹 뷰어 요청을 공개 전문 API라고 간주하지 않는다. 전문 연결은 실제 공급 경로·주소 체계·이용 조건이 확인돼야 구현한다. 현재 세 검색 컬렉션이 국문 시조·가사·고전소설 전체를 포괄하는지도 확인되지 않았다.

[저작권 정책](https://www.itkc.or.kr/content/contents.do?menuId=112)과 API 소개를 함께 기록한다. 이번 구현은 공식 검색 응답 전달 범위이며, 전체 데이터 다운로드·재배포 허용을 주장하지 않는다. 현대 번역·주석의 일괄 복제나 전문 데이터셋 구축은 별도 근거가 필요하다.

## 문법 도구 설계와 남은 조건

문법 API는 이번 ITKC 검색 규격에 없다. 각주·시소러스 검색을 문법 정답 엔진으로 표현하지 않는다. 후속 문법 도구는 `lookup_grammar` 후보 하나로 시작하며 입력은 개념/형태, 시대(현대/중세/근대), 선택적 용례다. 응답은 출처·설명·검수 용례·적용 범위·확인 불가 항목을 가진다. 자유 입력의 분석은 근거로 뒷받침되는 후보와 확정 결과를 구분한다.

구현 전에 현대·역사 문법 설명을 제공하는 공식 자료나 재사용 가능한 검수 자료가 필요하다. 현재 저장소에는 그 자료가 없으므로 생성 설명만 반환하는 도구는 만들지 않는다. 사용자가 별도 자료를 꼭 제출해야 하는 것은 아니며 공식 자료 조사를 이어갈 수 있다. 국립중앙도서관 키 신청은 이미 진행 중이며 발급 뒤 서지 검색을 실증한다.
