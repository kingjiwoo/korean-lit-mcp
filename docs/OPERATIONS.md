# 운영 및 배포

## 실행 조건

Python 3.13, 단일 프로세스·단일 인스턴스, SQL DB 없이 운영합니다. 공개 메타데이터만 메모리 캐시에 두며 재시작 시 사라집니다. 원문은 검수한 파일 버전과 함께 배포합니다.

| 환경변수 | 용도 |
| --- | --- |
| `MCP_AUTH_TOKEN` | 필수. 비공개 ASCII 접근 토큰, 최소 32자 |
| `MCP_ALLOWED_HOSTS` | 쉼표로 구분한 서버 호스트 이름. 기본은 localhost·127.0.0.1 |
| `MCP_ALLOWED_ORIGINS` | 필요할 때만 브라우저 Origin을 명시적으로 허용 |
| `MCP_HOST` | 기본 127.0.0.1. 컨테이너는 0.0.0.0 |
| `PORT` | 기본 8000. 컨테이너 기본 8080 |
| `WORKS_DIR` | 검수 원문 디렉터리. 기본 data/works |
| `NL_API_KEY` | 선택. 국립중앙도서관 외부 서지 검색 키 |

토큰은 비밀 관리 서비스나 실행 환경에서 전달합니다. `.env` 자동 로딩은 하지 않습니다. 토큰 누락·짧은 토큰은 시작 실패로 처리하고 공개 모드로 전환하지 않습니다. 키를 이미지·Git·URL에 넣지 않습니다.

## 로컬과 컨테이너

```sh
uv sync --frozen
# 실행 환경에 MCP_AUTH_TOKEN을 먼저 설정합니다.
uv run python -m korean_lit_mcp
docker build -t korean-lit-mcp:local .
docker run --rm --read-only --tmpfs /tmp -p 127.0.0.1:8000:8080 \
  -e MCP_AUTH_TOKEN -e MCP_ALLOWED_HOSTS=localhost,127.0.0.1 korean-lit-mcp:local
```

MCP 주소는 `http://127.0.0.1:8000/mcp`, 헬스체크는 `/health`입니다. 헬스체크가 성공해도 MCP 인증·도구 호출이 정상임을 보장하지 않으므로 두 경로를 모두 확인합니다.

컨테이너 실행 후 `TEST_MCP_URL`과 `TEST_MCP_TOKEN`을 테스트 환경에 설정하고 `uv run pytest tests/test_http_live.py`를 실행하면 실제 HTTP로 조회 → 판본·해시 전달 → 검증을 확인합니다.

## 파일럿 인증과 제한

고정 Bearer 헤더를 사용하는 파일럿 방식입니다. 교사별 계정·OAuth는 반복 사용과 접근 회수 수요를 확인한 뒤 추가합니다. 현재 공유 토큰 하나의 호출량을 함께 제한하므로 사용자별 집계라고 설명하지 않습니다.

인증된 HTTP 요청은 토큰당 분당 30개, 동시 요청 8개, 요청 본문은 최대 1 MiB입니다. 외부 검색의 처리 중 요청도 제한하며, 같은 질의는 하나의 업스트림 요청을 공유합니다. 제한 시 재시도를 안내하고 본문을 조용히 잘라 처리하지 않습니다.

토큰을 교체하고 서버를 재시작하면 이전 토큰의 접근이 거부되는지 확인합니다. 여러 프로세스·인스턴스의 메모리 상태는 공유되지 않으므로 이 설정으로 전역 쿼터나 분산 호출량을 보장하지 않습니다.

Origin이 없는 서버 간 클라이언트는 허용합니다. 브라우저가 Origin을 보낼 때는 Host·Origin 검사를 적용하며, 추가 허용 Origin은 실제 필요한 주소만 설정합니다. 기본값이 비어 있다고 모든 브라우저 Origin을 허용하는 것은 아닙니다.

## 로그와 외부 장애

요청 로그에는 상태·지연 등 내용 없는 지표만 남깁니다. 교사 본문·초안·인용과 비밀값을 기록하지 않습니다. FastMCP와 HTTP 라이브러리의 상세 로그는 운영 중 제한하고 외부 오류 추적·프록시에도 본문 수집을 켜지 않습니다.

기관 오류·인증 오류·쿼터 제한은 빈 성공 결과로 바꾸지 않습니다. 유효한 메타데이터 캐시가 있으면 조회 시각을 유지해 반환합니다. 외부 서지 검색이 실패해도 검수 원문 검색이 성공했다면 해당 결과와 외부 장애 안내를 반환합니다.

국립중앙도서관의 키 없는 오류 응답은 직접 확인했습니다. 인증된 검색 성공 응답은 발급 키로 별도 계약 검증이 필요합니다. 현재 XML fixture는 문서 필드를 사용한 합성 자료이며 실제 성공 응답이라고 표시하지 않습니다.

## 배포와 롤백

호스팅 계정·서비스·예산을 정하고 실제 Claude 계정에서 인증 호환성을 확인한 후 원격 배포를 진행합니다. 컨테이너는 비루트 사용자로 실행하고 비밀값을 빌드 시 주입하지 않습니다.

staging에서 검증한 이미지 digest와 자료 버전을 production으로 승격합니다. 환경마다 토큰과 키를 분리하고 실제 서비스의 호스트 이름을 `MCP_ALLOWED_HOSTS`에 설정합니다. 배포는 환경별로 직렬화합니다.

배포 후 `/health`, 무인증 거부, 세 도구 목록, 원문 조회와 검증을 확인합니다. 실패하면 이전 이미지 digest와 이전 비밀 설정으로 되돌리고 핵심 호출을 다시 확인합니다. DB 마이그레이션은 없습니다.

Cloud Run을 선택하면 기본 파일시스템의 영속성을 기대하지 않고 이미지 안 원문과 메모리 캐시로 실행합니다. 실제 배포 대상과 권한이 확정되기 전에는 운영 배포를 실행하지 않습니다.
