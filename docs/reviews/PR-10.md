# Vercel 배포 보완 검증 기록

기준은 PR #1~#10을 통합한 `develop`의 `b62d4d4`다. 사용자는 Vercel 배포와 준비된 `develop`의 production 승격을 지시했다.

## 구현과 교차 리뷰

루트 `app.py`와 Vercel Python 설정을 추가하고 CLI·Vercel이 같은 환경설정 함수를 사용하도록 했다. 명시적인 Host 목록이 우선하며, 생략하면 신뢰하는 Vercel 시스템 환경의 배포·브랜치·production 도메인을 사용한다. 요청 헤더에서 허용 도메인을 만들지 않는다. 원문은 번들에 포함하고 로컬 환경변수·인증 파일·개발 자료는 업로드에서 제외한다.

Claude Code의 응답 모델 `claude-opus-4-7`이 전체 diff·새 파일·호출부·테스트·현재 문서를 읽기 전용 스냅샷으로 검토했다. 결과는 검사 범위 승인, 증명된 결함 없음이다. 실제 project metadata에서 `autoExposeSystemEnvs=true`, production 브랜치 `main`과 GitHub 저장소 연결도 확인했다.

## 실행 결과

- 7개 설정·진입점 테스트를 추가했다. 실제 공개 Vercel HTTP 테스트를 포함한 전체 결과는 82개 통과다. 일반 테스트에서 외부 주소를 생략하면 81개 통과·1개 건너뛰기다.
- Ruff lint·format, mypy, Markdown lint와 `git diff --check`를 통과했다.
- 업로드 dry-run에서 30개 런타임·소스 파일과 원문을 확인했고 환경변수 파일·로컬 인증 파일은 없었다.
- 실제 Vercel 빌드는 Python 3.13과 `uv.lock`을 사용해 성공했다. 첫 배포는 CLI 기본 동작에 따라 production에 할당됐다. 최종 릴리스 뒤 `main` SHA에 맞는 배포를 다시 확인한다.
- 공개 `https://korean-lit-mcp.vercel.app/health`가 인증 없이 200을 반환했다. 이전 MCP 초기화와 현재 SDK의 도구 목록·원문 조회·인용 검증을 실제 공개 URL에서 확인했다.
- 실제 Claude Code가 공개 MCP의 세 도구를 순서대로 호출한 `tool_use` 이벤트를 확인했다. 검증 결과는 `all_submitted_exact=true`이며 「동백꽃」의 판본 해시는 저장소의 검수 파일과 같았다. Claude 웹의 실제 교사 사용과 구분한다.
