# ITKC 검색 확장 리뷰

기준: `develop`의 `db22bba`. 목표는 키 없는 공식 검색 API를 네 번째 MCP 도구로 연결하고, 호출 주소는 `ITKC_API_URL`로 설정하는 것이다. production 배포는 제외한다.

## 교차 리뷰

Claude Code CLI를 도구 없이 실행하고 전체 구현·계약·캐시·호출부·테스트·문서 diff 스냅샷을 전달했다. 실제 응답 모델은 `claude-opus-4-7`이다. 리뷰는 개발 브랜치 병합을 막는 확정 결함은 없다고 보고했으며 다음 권고를 검토했다.

- 검색 매핑, 크기 상한, 건수 초과, 지연 오류, 설정 누락의 MCP 경로 테스트를 보강했다.
- `defusedxml` 추가는 채택하지 않았다. UTF-8로 디코딩한 입력에서 DTD와 entity 선언을 파싱 전에 거부하며 응답을 2 MiB로 제한한다. 선언을 우회하는 구체적 입력은 리뷰에 없었다. 기존 서지 파서와 같은 규칙을 유지한다.
- 잘못된 환경변수는 기동 실패로 처리한다. 잘못된 설정을 조용히 무시하지 않는 운영 정책이며, 미설정은 정상 기동 후 도구 호출 시 설정 오류로 응답한다.
- httpx 상세 로그 제한은 기존 국립중앙도서관 클라이언트와 동일한 정책이다. 공개 검색어를 로그에 남기지 않는다.
- `itertext()`는 원문 문자 사이에 새 공백을 삽입하지 않는다. 실제 응답의 검색 강조는 이스케이프된 문자열로 보존한다.
- 페이지 끝의 빈 결과 문제는 현재 시작 위치가 0 고정이라 해당하지 않는다. 페이지네이션을 추가하면 별도 계약 검증이 필요하다.
- source 중복은 기존 검색 결과 항목의 출처 표시 계약과 일치한다.

## Ponytail 리뷰

What this change does: Adds public classical search snippets as one tool. Reuses the existing memory cache and error envelope.

기존 cache와 계약·에러 모델을 재사용하고 새 의존성은 추가하지 않았다. 국립중앙도서관과 ITKC의 응답 구조가 달라 파서를 합치지 않았다. 실제 호출 경로·MCP 등록·로그 허용 목록·도구 목록 테스트를 함께 확인했다. 추가 확정 결함 없음.

## 검증

Ruff lint·format, mypy, pytest, Markdown lint를 실행했다. 실제 ITKC 응답 GO_BD·MO_BD·KP_BD·MO_GS를 파서로 처리했고 새 클라이언트로 MO_BD 검색도 성공했다. 실제 외부 응답은 fixture로 저장하지 않았다. 원격 MCP 테스트는 production 배포 전이므로 실행 대상에서 제외했다.

전문 공급 경로와 현대 전사·번역·주석의 재사용 조건, 별도 문법 근거 자료는 아직 미확인이다. 이 도구의 성공을 모든 고전 작품 전문 제공 완료로 표시하지 않는다.
