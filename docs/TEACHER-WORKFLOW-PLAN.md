## W-01 계약

work_id·edition_id와 query(최대 200자)를 받는다. match_mode 기본 exact, 선택 orthography는 기존 NFC·공백·따옴표 비교를 재사용하되 모호한 유사어 검색은 하지 않는다. 문맥은 물리 행 전체 대신 원문 코드포인트 기준 context_chars(기본 80, 최대 300)로 제한해 긴 한 행으로 응답이 커지는 것을 막는다. 후보 기본 3·최대 5개이며 추가 후보 존재를 알린다. 문맥이 옛한글 조합 중간에서 잘릴 수 있으므로 문맥 자체를 정본 구절로 확정하지 않는다. 검색 일치는 원문 그대로의 text·0부터 시작하는 start/end(끝 제외), 1부터 시작하는 행 주소·출처·판본 해시를 반환한다. 정확 일치도 여러 위치면 선택을 요구한다. 표기 차이 검색에서 원문 구간이 600자를 넘으면 본문을 반환하지 않고 생략 건수를 표시한다.

## W-02 계약

기준은 고정 작품·판본·해시 또는 교사 제공 source_text 중 하나다. 입력은 원문 start/end와 quote를 갖는 segments(최대 10개)이며 각 원문 구간은 최대 4000자·선택 구간 합계 10000자다. 원문 좌표는 Python 문자열 코드포인트 기준, 끝 제외다. 구간은 오름차순·비중첩이어야 하며 그 사이를 명시적 생략으로 보고한다. 자동으로 생략 기호나 자연어 편집 의도를 추론하지 않는다.

규칙은 기본 모두 끔이다. ignore_whitespace와 호출자가 명시한 숫자 대괄호 표지(drop_note_markers, 예 `[5]`) 제거만 지원한다. 표지의 의미가 실제 각주인지 서버가 인증하지 않으며 명시한 문자 제거 이력을 보고한다. 임의 정규식·현대어 변환·옛한글 정규화·어휘 교정은 없다. 편집으로 빈 문자열이 된 경우 통과하지 않는다. 반환 상태는 exact / edited_match / mismatch이며 edited_match도 원문 그대로의 일치나 문학적 타당성으로 표시하지 않는다. 선택 원문·변환 문자와 원문 위치 대응·삭제 범위는 요청 중에만 계산한다. 원문·입력 문자열 자체는 변경하지 않는다.

## W-03 계약

같은 기준 본문을 사용하는 blocks(지문 passage / 선지 option / 해설 explanation)를 받는다. 블록 ID는 유일해야 한다. 각 citation은 블록 안 start/end와 대응 원문 source_start/source_end를 명시한다. 대조할 문자열은 서버가 블록에서 직접 잘라 별도 quote 복사본 불일치를 막는다. 여러 인용을 연결한 편집 지문은 각 인용 영역을 각각 지정하며 사이의 생략 표시도 미검증 범위로 남긴다. 블록당 인용 순서와 비중첩·모든 범위·입력 총량을 검사한다. 블록 순서나 선지의 의미를 판단하지 않는다.

W-02 엔진을 재사용해 블록별 결과, 검토 필요 건수, 실제 대조한 영역과 나머지 모든 미검증 영역을 반환한다. 표시 없는 인용을 자동 추출하거나 초안 전체를 인증하지 않는다. 구조화된 JSON 보고서를 먼저 제공하며 파일 업로드·HWP/PDF 해석·OCR·별도 내보내기 엔진은 이번 범위에 넣지 않는다. 최대 10블록·총 20인용·블록 본문 합계 30000자·대조 원문 합계 10000자로 요청/응답 작업량을 제한한다.

## 회귀와 제한

기존 verify_quote의 판정·source_text 모드·오류·입력 상한과 기존 도구 이름은 유지한다. 새 도구는 읽기 전용이다. 합성 예제와 이미 이용조건을 확인한 내장 원문으로 위치·옛한글·한자·인코딩·각주 제거·부정어 변경·생략 순서·오래된/다른 판본 해시·오류·입력/출력 예산을 검사한다. 실제 교과서 적합성·교사 편집 규칙 감수·학교 클라이언트 실증은 후속이다. 문항 의미·정답·작가 귀속을 자동 인증하지 않는다.
