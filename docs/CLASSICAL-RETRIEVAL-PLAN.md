# 문학 작품 탐색과 검수 원문 공급 PR 계획

## 목표와 출발점

2026-11-04 사용자가 제시한 운영 결과에서는 사미인곡·청산별곡 검색에 음악 자료가 다수 나오고 응답이 잘렸다. ITKC의 동명 기사·관련 기록은 실제 작품 원문을 제공하지 못했다. API 인증·HTTP 성공과 수업에 쓸 원문 확보를 별도 완료 조건으로 관리한다.

기존 [#30 검수 고전 판본 공급](https://github.com/kingjiwoo/korean-lit-mcp/issues/30)을 중심으로 아래 여섯 작업 PR로 구체화한다. 아래 R-01~06은 계획 단계이며 GitHub PR 번호를 예약한 것이 아니다. 이미 완료한 #28/#29/#31의 API 연동·저자 역할·실패 계약을 재구현하지 않고 보완한다.

목표 확인 작품은 사미인곡·청산별곡·관동별곡·홍길동전·구운몽·규원가다. 여섯 편은 회귀 기준이며 전체 지원 범위의 상한이 아니다. 현대 문학의 기존 검수 원문·교사 제공 본문·문법 조회도 유지한다.

## R-01: 작품과 레코드의 관계

검수 대상은 작품명·검토한 한자/옛표기 이칭·귀속 이견·수록 문헌 후보와 근거 URL이다. 기존 `work_identity.py`를 우선 재사용하며 제목으로 다른 기관 레코드나 판본을 합치지 않는다. 판본 연결은 기관 고유 ID와 대조한 명시적 매핑이 있을 때만 확정한다.

사미인곡의 발견용 작가 정보로 임하필기·이계집의 문헌 저자를 덮어쓰지 않는다. 규원가 귀속 이견도 유지한다. 청산별곡·관동별곡·구운몽 등 현재 누락된 기준 작품을 추가하되 다른 작가·시대의 동명 작품을 단일 후보로 강제하지 않는다.

ITKC 제목 검색의 발췌가 제목을 반복하는 사례는 본문 언급 근거가 아니다. 현재 `classify_record`가 검색 대상을 받지 않고 snippet 문자열을 `body_mention`으로 분류하는 부분을 수정한다. 제목의 정확 일치·제목 안 언급·실제 본문 발췌의 언급·미확인을 구분하고, 관련 글 제목에 작품명이 있다고 작품 전문으로 표시하지 않는다. 기존 필드의 호환·새 분류 의미를 계약과 문서에 함께 적는다.

## R-02: 기본 문학 탐색과 짧은 응답

기본 사용자는 문학 작품을 찾는 교사다. 원시 서지 전체를 그대로 주요 결과로 올리지 않는다. 음악·영상·연구 기사·현대 개작·작품 원문 판본을 자료유형과 확인 근거에 따라 구분하며, 판단할 수 없으면 미확인으로 남긴다. 현대 번역·선집·주석본은 원작의 표기 기준 원문과 구별한다.

일반 서지 탐색 의도는 명시적 선택으로 유지하되 기존 `nl_category`와 충돌하지 않게 최소 계약을 정한다. 문학 탐색을 무조건 `old_books`로 고정하지 않는다. 그러면 현대 문학과 현대에 간행한 고전 판본을 놓칠 수 있다. 기존 두 검수 작품과 작가 검색을 회귀 기준에 포함한다.

작품 제목에서 직접 원문을 찾지 못하면 검수된 수록 문헌 후보를 다음 경로로 제시한다. 송강가사·악장가사의 검색 성공만으로 개별 작품이 그 판본에 실제 수록됐다고 확정하지 않는다. 미확보 작품은 0건으로 사라지게 하지 않고 작품 후보와 원문 미확보 상태를 구분해 전달한다. 서버가 클라이언트 대화의 원래 의도를 자동 판독한다고 주장하지 않는다.

응답에는 요청 작품·실제 검색 범위·원문 확보 상태·선택 가능한 판본/다음 경로를 먼저 보여 준다. 문헌 저자·작품 작가·원문 조회 가능 ID를 구분하고 반복되는 출처·장문의 설명을 줄인다. 기본 후보는 최대 3개, 해당 경로의 기본 MCP `tools/call` 결과 전체를 UTF-8 직렬화했을 때 16 KiB 이내로 하는 예산을 먼저 검사한다. 출처·판본·권리·오류는 예산을 맞추려고 숨기지 않는다. 서지 상세 모드와 원문 범위 조회는 별도로 상한을 유지한다.

검색 요약을 위해 메타데이터 표시를 줄였으면 생략 사실과 상세 출처 경로를 표시한다. `get_passage`의 원문 문자열은 요약하거나 정규화하지 않는다. 실제 클라이언트의 출력 잘림은 서버 바이트 수와 별도로 관찰하며 완전 방지를 보장하지 않는다.

외부 탐색은 기관별 호출 수·응답 크기·타임아웃을 제한하고 검색 범위/의도를 캐시 키에 반영한다. 입력에서 임의 URL이나 기관 엔드포인트를 받지 않는다. 기관 장애를 빈 성공·작품 부재로 바꾸지 않고 부분 결과의 실패 범위를 남긴다.

## R-03~05: 실제 원문을 공급하는 조건

[NL 실증](decisions/0005-nl-authenticated-search.md)의 구형 뷰어 진입 HTML 200과 이동 경로 404를 출발 근거로 삼는다. 실제 브라우저의 정상 동선·세션·리다이렉트를 먼저 관찰하고, 이미지/PDF/텍스트 제공과 로그인·기관망·유료 여부를 구분한다. 접근 제한을 우회하지 않는다. 실패한 단일 URL만으로 기관 전체 원문 부재를 확정하지 않는다.

공개 전문 경로가 없으면 공개 파일·다른 공식 아카이브 등 출처를 비교한다. HTML 내부 통신이 발견돼도 공개 API 계약·허용 범위가 확인되지 않으면 제품 커넥터로 승격하지 않는다. 새 API 호출 주소는 환경변수로 관리한다. 자료의 열람 허용과 복제·변경·재배포 허락을 별도로 확인한다.

판본별 근거 표는 작품 후보, 수록 문헌, 기관/판본 ID, 제공물 유형, 실제 접근 결과·시각, 권리와 출처표시 조건, 텍스트 인코딩·해시, 대조 기록, 해결되지 않은 조건을 포함한다. 추측·미확인은 빈 성공으로 채우지 않는다. R-03 조사 기록 PR은 미해결 결론도 병합 가능하지만, 그것이 R-04 착수 조건을 충족한 것은 아니다.

공급 가능한 판본은 기존 manifest와 파일 적재 경로를 우선 사용한다. 원문과 현대역·주석을 분리하고 아래아·옛한글 조합·한자·이체자·띄어쓰기·줄바꿈을 해당 판본대로 보존한다. 원문 파일의 자동 포맷이나 모델 기억을 이용한 복원을 하지 않는다. OCR이 필요하면 원본과 별도 자료로 보관하고 문자 대조·검수자/방법·수정 이력·새 해시를 기록한 판본만 제공한다.

문항 생성·해석은 클라이언트가 수행한다. 서버는 원문 조회와 인용 문자열 대조를 담당하며 문학 해석·정답 타당성·제공 본문의 정본 여부를 자동 인증하지 않는다. 이미지/PDF나 링크만 확보한 작품은 실제 원문 텍스트 공급 완료로 표시하지 않는다.

합성 XML·합성 문장은 오류와 계약의 회귀 검사에 사용한다. 고전 전문 공급 성공은 실제 재사용 가능한 판본으로 별도 증명한다. 전체 계획의 핵심 완료 기준은 실제 고전 원문으로 검색 → 판본 선택 → 원문 확보 → 인용 대조가 되는 것이다. 식별·안내·계약만 구현한 상태를 원문 검색 완료로 표시하지 않는다.

## 병합·릴리스와 보고

각 작업 브랜치에서 PR 목표·외부 근거·회귀 사례·미확인 조건을 기록하고 `pr-cycle`의 구현·독립 리뷰·ponytail 검토·필수 검사를 수행해 develop으로 squash 병합한다. 현재 문서는 계획 산출물이며 구현이나 새로운 외부 공급 실증을 수행한 기록이 아니다.

검색 개선(R-01/R-02)은 먼저 릴리스할 수 있으나 원문 제공 범위를 늘렸다고 설명하지 않는다. 원문 공급 릴리스는 실제로 확보·검수한 작품/판본을 명시하고 R-06을 통과한 후보만 main에 merge commit으로 반영한다. Vercel production의 Git SHA와 공개 HTTP/MCP 호출을 확인한 뒤 main 이력을 develop에 동기화한다.

README·교사 안내에는 지원 작품/판본, 미확보 상태, 실제 조회 예시와 검사 범위를 함께 반영한다. 키·교사 본문·초안은 로그·fixture·PR에 넣지 않는다. DB·제품 LLM·사용자 로그인은 추가하지 않는다. 국립중앙도서관 키 발급을 추가 텍스트 공급·재배포 허락의 대체 조건으로 보지 않는다.
