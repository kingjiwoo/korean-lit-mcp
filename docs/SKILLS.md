# 스킬 운영 체계

이 문서는 Claude와 Codex가 같은 기준으로 작업하도록 하는 프로젝트 공통 운영 규칙입니다. 도구별 지침은 `CLAUDE.md`와 `AGENTS.md`에 두고, 작업 절차와 품질 기준은 이 문서에서 관리합니다.

## 스킬의 의미

스킬은 특정 작업을 반복 가능하게 만드는 작은 작업 지침입니다. 스킬 하나는 다음을 명확히 해야 합니다.

- 언제 사용하는가
- 입력과 전제조건은 무엇인가
- 수행 순서는 무엇인가
- 완료 기준과 검증 방법은 무엇인가
- 실패 시 중단하거나 보고할 조건은 무엇인가

## 우선 적용 순서

1. 실행 환경의 상위 지침과 사용자 요청
2. 저장소 공통 규칙(`AGENTS.md`, `CLAUDE.md`)
3. 해당 작업의 스킬 문서
4. 일반적인 구현 관례

서로 충돌하면 상위 순서를 따르고, 안전·데이터 보존·보안 관련 규칙은 생략하지 않습니다.

## 초기 스킬 목록

현재는 과도한 자동화를 만들지 않고 다음 네 가지부터 운영합니다.

| 스킬 | 사용 시점 | 완료 기준 |
| --- | --- | --- |
| 탐색/설계 | 새 기능, 구조 변경 전 | 영향 범위와 결정 사항이 문서화됨 |
| 구현 | 코드·설정·문서 변경 시 | 최소 변경이 반영되고 검증됨 |
| 검증 | 기능 변경, 버그 수정, 배포 전 | 관련 테스트 또는 재현 절차 통과 |
| 릴리스 | `main` 반영 또는 배포 시 | 변경 내역, 버전, 배포 상태 확인 |

## 스킬 추가 규칙

반복 작업이 두 번 이상 발생하고 실수 가능성이 있으면 스킬 후보로 등록합니다. 실제 실행 스킬은 `.agents/skills/<name>/SKILL.md`에 두고 `.claude/skills/<name>`에서 같은 폴더를 연결합니다. 초안과 설명 문서만 있는 경우 실제 등록된 스킬로 표시하지 않습니다.

현재 등록한 `check-project`는 Python·Markdown 필수 검사를 실행하고 외부 검증의 한계를 보고하는 절차입니다. Codex의 `$check-project`와 Claude의 `/check-project`에서 사용합니다. 두 경로가 같은 원본을 읽는지 확인하고, 연결이 지원되지 않는 환경에서는 `AGENTS.md`의 명령을 직접 실행합니다.

스킬을 만들 때는 아래 형식을 사용합니다.

```md
---
name: <skill-name>
description: <이 작업을 수행하는 시점과 결과>
---

# <스킬 이름>

## 목적
## 사용 시점
## 입력과 전제조건
## 절차
## 검증
## 실패·중단 조건
## 결과 보고 형식
```

스킬은 제품 기능을 임의로 결정하지 않습니다. 제품 결정이 필요하면 사용자에게 확인하거나 이슈/PR에 결정 근거를 남깁니다.
